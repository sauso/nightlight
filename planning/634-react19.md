# #634 — React 19 migration plan

Status: plan only (T0, docs). The migration itself is T2-ish for the frontend: no stored data is touched, but
every screen renders through it and CI never drives a browser on a dev PR. Facts about React 19 are from memory
and from the issue text; mark: **(unverified)** = I could not check it in this session (no access to React's
or the packages' changelogs). The app facts come from `frontend/package.json` and greps of `frontend/src`
and `frontend/test`.

## ⚠️ Dependabot PR #731 must not be merged on its own

[#731](https://github.com/sauso/nightlight/pull/731) bumps **only `react-dom` 18.3.1 → 19.3.1**. `react-dom@19`
needs `react@19` (its peer dependency is the same version), so merging it alone leaves `react@18` with
`react-dom@19` — the same mismatch that made #532 fail the frontend job. It also moves nothing else the
migration needs (testing library, browser checks). **Do not merge #731 without React 19 itself, in the same
branch, after the steps below.** Close it when the migration PR is opened, or leave it for the real PR to
supersede. Also note: `.github/dependabot.yml` has no `ignore` entry for React majors (the frontend block has
no `ignore:` at all), so contrary to the note in #634 Dependabot is *not* currently told to skip them; adding
`ignore: react, react-dom, @types/*` for `version-update:semver-major` is a one-line change worth doing until
this lands. (Not done here: this PR is docs only.)

## 2. What React 19 changes, and whether this app uses it

| React 19 change (from memory, **unverified** against the official upgrade guide) | Grep result in this repo | Impact |
|---|---|---|
| `ReactDOM.render` / `hydrate` removed | none; only `react-dom/client` `createRoot` (`src/main.jsx:2,12`) | none |
| `forwardRef` no longer needed (still works, deprecated path) | none in `src` | none |
| `defaultProps` removed for function components | none | none |
| `propTypes` ignored | none | none |
| String refs removed | none (`ref="` only matches nothing relevant) | none |
| Legacy context (`contextTypes`, `getChildContext`) removed | none; modern `createContext`/`useContext` in 4 files | none |
| `react-dom/test-utils` (`act`, etc.) removed | tests import `act` from `@testing-library/react` (24 files); no `react-dom/test-utils` import | none, as long as RTL ≥ 16.1 (installed 16.3.3 peers allow 19) |
| `findDOMNode`, `unmountComponentAtNode` removed | none | none |
| Ref callbacks may return a **cleanup function**; an implicit-return arrow is now treated as cleanup | `ref={...}` grep shows only `ref={someRef}` object refs (14 files, `useRef` in 23 files); no inline callback refs found | verify by re-grep at migration time |
| `ref` is a plain prop for function components | no `forwardRef` to migrate | none |
| StrictMode: re-uses memoised results on the second render and double-invokes ref callbacks in dev | app already comments on StrictMode double-invocation (`src/main.jsx:13`, `LiveMonitor.jsx:121`, `DetectionSettings.jsx:102`, `Login.jsx:35`, `lib/detectionSaves.js:365`, `lib/demoStatus.js:16`) | lowest risk: it was written for it; still re-test mount/unmount effects |
| Error handling: errors in render are no longer re-thrown the old way; `onUncaughtError`/`onCaughtError` root options | two class components: `components/ErrorBoundary.jsx`, `lib/lazyPage.jsx` (error boundary + `lazy` with a retry, `lazyPage.jsx:~71`) | **medium**: check boundary behaviour and the chunk-reload recovery on a stale deploy (browser check, §5) |
| `lazy`/`Suspense` behaviour (pre-warming siblings, fallback timing) | `lib/lazyPage.jsx` | medium: check the page-transition flash and the retry path |
| `useRef` requires an argument (TypeScript types only) | JS project, no types | none |
| `element.ref` access / `React.createElement` changes | `React.createElement` only in tests | none |
| Document metadata hoisting (`<title>`, `<meta>`, `<link>` in components) | none rendered in components | none |
| `React.Children`, `unstable_batchedUpdates`, `flushSync`, `createPortal` | none of the removed ones; **no `createPortal`** in `src` | none |
| Test environment: `IS_REACT_ACT_ENVIRONMENT` warnings text changed | RTL sets it | watch for new console warnings; `frontend/test/setup.js` (listed in `vite.config.js:58`) has no console hooks, so warnings do not fail tests: diff the warning output old vs new by hand |

Net: no removed API is used. The risk is behavioural (refs, effects, error boundaries, Suspense) in components that
use them heavily: `CameraTile.jsx`, `HlsPlayer.jsx`, `LiveMonitor.jsx`, `MediaPlayerModal.jsx`.

## 3. Dependencies that need a compatible release

Not "needs a release" but "needs verification", in order of risk:

1. `@dnd-kit/core` + `sortable` (the live grid reorder): declared peer range allows 19; **check their changelog /
   issues for React 19 and StrictMode problems; mark unverified until a real drag works** (§5).
2. `@testing-library/react` 16.3.3: peers include 19; confirm no `act` warnings in the 24 files that use it.
3. `react-router-dom` 7.x: peers `>=18`; v7 is the React-19-era line **(unverified)**.
4. `lucide-react`: peers list 19. No action beyond the lockfile oddity above.
5. `hls.js`, `@vitejs/plugin-react`, `vitest`, `jsdom`: no React peer. `plugin-react` 6 should handle 19's
   automatic runtime **(unverified)**.
6. Anything pulled in transitively that pins React: check `npm ls react react-dom` after the bump — a second copy
   of React in the tree is the usual failure.

## 4. Order of small PRs

1. **Prep (T1, no behaviour change):** a Dependabot `ignore` for React majors; re-run the audit greps from §2 and
   record them in the PR; fix anything that the greps newly find (e.g. an inline callback ref returning a value).
   Add a build check to the plan (below).
2. **Tooling PR (T1):** make CI able to prove the upgrade — at minimum run `npm run build` in the frontend job
   (the issue says CI never builds the production bundle on a dev PR), and decide how the e2e run (`e2e/`,
   Playwright, needs Docker; workflow `.github/workflows/e2e.yml`) is triggered for a React PR.
3. **The upgrade PR (T2-style review):** `react`, `react-dom` and any peer-coupled package in one commit, per-test
   result diff old vs new (same recipe as the vitest 5 upgrade, per #634), `npm run build`, full e2e, then the
   staging click-through (§5). Supersedes #731 and any react Dependabot PR.
4. **Follow-ups, only if wanted:** drop now-unneeded patterns, adopt `ref`-as-prop, use `onCaughtError` /
   `onUncaughtError` logging. Not part of the upgrade PR.

Rollback is a revert of PR 3 plus lockfile; keep the staging image tag of the last React 18 build.

## 5. Browser checks required (a green unit job proves little)

On staging (`:dev` image), real browsers, in this order:

* **Live grid:** all tiles start, WHEP/WebRTC playback connects, reconnect after a camera restart, and the
  tile-level audio button (`CameraTile.jsx`, the `Volume2` control) toggles without a re-mount.
* **WHEP and HLS players:** WebRTC tile and the HLS fallback (`HlsPlayer.jsx`, hls.js 1.7.3): start, stall
  recovery, unmount while loading (no leaked `Hls` instance, no console error), switching between tiles.
* **Picture-in-picture:** web PiP via `video.requestPictureInPicture()` (`CameraTile.jsx:554`), the case where
  fullscreen and PiP are exited in order (`:484-488`), and PiP when navigating to another route.
* **Native app (Capacitor WebView, iOS and Android):** Activity PiP (`enterNativePip`), background listening
  (`setBackgroundListening`), install-prompt suppression (`InstallPrompt.jsx:25-33`). The WebView is a different
  engine from the desktop browsers; this cannot be reproduced in jsdom or desktop Chrome.
* **Focus handling:** modal open/close, route changes, the inert/hidden live monitor (see #376 — if that has
  shipped, re-test it; if not, note that its behaviour will change under 19's ref/effect rules).
* **Error recovery:** force a render error (error boundary screen) and a stale-chunk load failure after a deploy
  (`lazyPage.jsx` retry) — the two class components.
* **Drag and drop:** reorder tiles (admin) and the child/camera reorder lists.
* **Sleep screens:** the morning review, the timeline, event frames, the recompute card.
* **Settings forms and unsaved-change guards:** unsaved-warning prompts rely on effects/cleanup.
* **PWA:** install, service-worker update, and reload after a deploy.

## 6. Risks

* No removed API found, so the dominant risk is **effect/ref ordering and StrictMode** around streaming
  players (leak or double-connect), and **error-boundary behaviour**.
* `@dnd-kit` compatibility is the least certain third party **(unverified)**.
* A second copy of React in the tree (hooks-invalid-call errors) from a stale lockfile.
* CI blind spots: no bundle build, no browser on a dev PR (issue text) — address in PR 2 before relying on green.
* Test-suite noise: new `act`/console warnings may change snapshots of console output; the suite does not
  fail on warnings (`frontend/test/setup.js` has no console hooks), so a new `act` warning would pass silently.
* The native app ships its own WebView version: users on old WebViews may not support what the bundle targets;
  React 19 itself needs no new browser features **(unverified)**.
* Time: nothing is urgent (no deadline in #634).
